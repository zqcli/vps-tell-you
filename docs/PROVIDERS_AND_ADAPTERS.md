# 提供商、适配器实例与服务器

## 三层关系

业务模型仅有 **Provider → AdapterInstance → Device**：

- 提供商是服务器的业务归属。每个提供商可有多组独立适配器实例。
- 适配器实例记录类型、面板地址及不透明 secretRef。相同类型共用协议实现，每个实例有独立授权周期。
- 服务器只有一个当前提供商，最多一个适配器关联；手动服务器可暂不指定提供商、暂不关联适配器。

凭据不是第四层业务入口。秘密仍由现有设备安全存储保护，SQLite 只存引用；面板授权与 SSH 凭据互不转换。保留历史 `cloud_accounts` 表及 `CloudAccount` / `CloudProvider` API 名称作为兼容边界；新语义分别为 `AdapterInstance` 与 `AdapterType`。它们不是业务提供商。

## 添加和继续导入

服务器页统一“添加”入口先选择或新增提供商，然后选择手动填写或自动读取。未指定提供商只支持手动方式，之后可在详情补充归属。

手动方式沿用现有六项资源编辑器和费用表单：IP、hostname、CPU、内存、磁盘、流量。容量与单位同行，流量周期独立，未知可留空，费用保持可选。选择提供商不会授予任何 API 凭据或建立连接。

自动方式选择本提供商下的已有实例，或选择类型并验证新凭据。查询使用原有有界、可取消、只读接口，所有分页完整成功后才发布快照。V1 / RackNerd 客户端接口返回设备资源；V2 返回当前授权可见设备。账号级授权只返回一台时仍是账号范围，不能用结果数量更改范围。

预览标记已存在、资料完整和待补填。SolusVM 1 / 2 与 RackNerd 都必须确认完整六项资源才能新导入。零值或空值保持待补填，绝不自动解释为不限流量；只有明确的不限量来源或用户选择才生效。API 不提供的 hostname/流量等字段在本地补充，不猜字段、价格或 SSH 配置。修改 API 值后清除该字段的 API 来源标记，原始观测不被本地补填覆盖。

新实例先独立提交授权元数据和安全存储引用，再逐台导入。每台服务器、关联和默认提醒记录在同一事务内提交。局部资料错误可单独补正；取消、授权变化或存储失败停止余项，已经成功的服务器保留。结果明确区分已保存实例、已导入、已存在、失败及未处理。重试只处理未完成项，不重建实例、不重写同一凭据，不自动刷新后续跑旧选择。写入已提交但重读失败时先显示成功事实，并要求本地重读后再修改。

## 身份、排重与授权范围

- SolusVM 2 的身份域包括适配器类型、规范面板 origin、已验证远端用户 ID、项目 ID 和设备 ID，同时保留非空 UUID 的一致性围栏。不同凭据实例看到同一身份时只提示已有记录，不移动其归属、关联或秘密。已归档设备也参与排重；历史多重重复保留并列出，不能任意选一条覆盖。
- IP、hostname、面板地址或名称单独都不是设备身份。相同 IP 的不同远端 ID 可代表不同设备，不自动合并。UUID 冲突不能降格为按 IP 猜测。
- SolusVM 1 与当前 RackNerd Client API 没有稳定设备 ID。`single` 只在该本地实例的凭据授权周期内有效。首次关联时固定原本地服务器 ID；解绑、归档或更改业务归属不释放此 pin。只能重连原记录，不能把旧单机 Key 转给另一条 VPS。
- V1 / RackNerd 的单设备 pin 是本地安全围栏，不能证明服务端仍是原 VPS。重新授权需明确确认解除旧关联，开启新周期并重新选择；不按相同 URL/IP 默认同一台。
- 未确认范围拒绝新关联。业务提供商、类型、授权范围及实例 generation 在写入事务内再次验证；旧页面、旧验证、旧查询和延迟结果不能恢复已撤销的关系。

现有服务器可从已保存、同提供商的授权观测中显式选择关联，页面不会自动连接面板。更改业务提供商时必须先明确确认解除当前适配器关联，不会自动获得新 Key。确认的影响包括具体服务器及原实例；弹窗期间关联变化会使旧确认失效。

## 迁移与保留

合并版本为 **schema v11**。上游提供商结构和本地 RackNerd 曾各自使用不同结构的 v10；升级依据实际表结构区分，并在同一次 SQLite 升级事务中保留 / 新增 `providers`、服务器 provider 引用、实例 business-provider 引用、授权范围及单设备 pin，同时保留 RackNerd 类型约束。旧实例 ID、端点、secretRef、观测、关联，以及服务器原文字、版本、资源、账务、SSH 等字段保留。迁移不读取钥匙环，不请求面板，不按 URL/IP 合并设备。

旧实例所有已关联设备的原 vendor 一致且不是占位文字时，可归入对应提供商。混杂、仅占位或没有关联设备的旧实例，各自进入独立的“归属待确认”提供商，不能共用一个会扩权的未知桶。确认前只允许原关系继续只读刷新，不新增授权、导入或绑定。确认整个实例归属时列出受影响设备，事务修改关系并使旧操作失效，保留原 vendor 文字。

若旧 V1 / RackNerd 数据存在多个矛盾绑定，迁移安全失败，整个 schema 升级回滚，原库保留；不任取一条、不删旧资料。较新 schema 仍禁止旧客户端破坏性降级。

解除某服务器关联、删除适配器实例都保留本地服务器、资源、账务和 SSH。删除实例会解除其关联并安排无引用秘密清理，失败保留清理提示，不自动销毁远端资源或停止厂商扣费。

## 台账备份边界

JSON v1 仍是未加密的部分范围台账文件，不新增 provider 结构、适配器、观测、关联、secretRef 或凭据导出。原 vendor 文字保持白名单字段；新建未指定记录若为空，仅在导出投影为旧格式兼容的“服务商待填写”，本机原文字不改。

恢复仍只允许空台账，所有恢复服务器的 providerId 为空，不因同名提供商、IP 或现存授权自动重连。即使目标设备已经保存适配器实例，恢复也不会使其获得新关联。这不是完整提供商关系备份或密钥迁移。

## 界面与验证边界

界面复用正式应用主题、卡片、菜单、表单和四个主 Tab，提供商→实例→服务器及详情反向跳转使用原 Navigator；无独立凭据业务层。中文与 English 使用同一 ARB 目录，支持窄屏、大字和深浅色。

此增量只使用合成 SQLite、伪安全存储及既有本地协议 fixture。原生构建、完整测试、独立 review 和同 SHA CI 结果以 STATUS / ACCEPTANCE 的本次完成记录为准。Android/iOS 真机兼容、真实厂商字段与手机安全存储不因 Linux 自动测试而被宣称通过；本次不自动生成 APK。
